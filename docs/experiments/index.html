Kloonaa ja kokeile#

Kloonaamalla saat lähdekoodin, sisältömäärittelyt, testit ja dokumentaation. Voit käyttää niitä oman kokeilun pohjana tai antaa ne uudelle koodaavalle mallille. Ensimmäiseksi kannattaa luoda tyhjästä erillinen kokeilumaailma.

Mitä kloonissa on ja mitä tarvitaan erikseen?#

Kloonissa mukana Erikseen hankittava tai luotava
Python-moottori, ajajat ja malliadapterit Python-ympäristö ja halutun mallireitin palvelut
Tarkistettu sisältö ja alustusmäärittelyt Uuden maailman oma datakansio
Testit ja CharacterLab-skenaariot Mallien käyttöoikeudet, kirjautumiset ja mahdolliset paikalliset painot
Selaimessa toimivan katselimen lähteet Haluttaessa oma julkaisu ja palvelinasennus
Historiallista esimerkkidataa Nykyisen maailman täysi, eheä tilannekopio, jos tarkoitus on jatkaa juuri sitä

Lähdekoodirepositorio on tällä hetkellä yksityinen. Julkisen katselimen tai tämän oppaan avaaminen ei anna siihen käyttöoikeutta.

Alla olevat komennot on tarkoitettu Linuxiin tai WSL:ään ja testattu Python 3.12:lla. Tämä ensimmäinen kokeilu ei tarvitse mallipalvelua, Nodea, tausta-ajastinta tai dokumentaatiosivun rakennustyökaluja.

1. Ota lähdekoodi ja kirjaa versio#

Kun GitHub-käyttöoikeus on käytössä:

git clone https://github.com/OssiRuhanen/The-many-remembered.git
cd The-many-remembered
git rev-parse HEAD

Säilytä tulostettu commit-tunniste kokeen muistiinpanoissa. Se kertoo, mitä sääntöjä ja sisältömäärittelyjä käytit. Kloonaus ei käynnistä asukkaita tai asenna palveluita.

2. Luo maailma ilman mallikutsuja#

Suorita seuraava kloonin juuressa. mktemp tekee uuden datakansion erilleen lähdekoodista. Pidä sama terminaali auki seuraavaa vaihetta varten.

export WORLD_DEMO_ROOT="$(mktemp -d)"
python3 - <<'PY'
import json
import os
from pathlib import Path
from engine.world import WorldStore

root = Path(os.environ["WORLD_DEMO_ROOT"])
store = WorldStore(root)
store.bootstrap()
result = store.apply_action("mira", {"type": "OBSERVE"})
assert result["status"] == "accepted", result

# Avaa sama maailma uudelleen ja lue pysyvästi tallennettu tila.
state = WorldStore(root).read_authoritative_state()
assert (root / "state/events.jsonl").stat().st_size > 0
print(json.dumps({"root": str(root), "tick": state["tick"],
                  "result": result}, ensure_ascii=False, indent=2))
PY

Tuloksessa näkyy accepted, datakansion sijainti ja tikki 0. Havainnointi on tässä yksittäinen validoitu teko; se ei käynnistä tikkejä eteenpäin vievää maailman istuntoa. Maailma jää kyseiseen datakansioon myöhempää tarkastelua varten. Tilapäiskansio ei ole pitkäaikainen varmuuskopio.

3. Katso kokeilumaailmaa selaimessa#

python3 -m scripts.world_viewer --root "$WORLD_DEMO_ROOT"

Avaa paikallinen katselin. Se näyttää tämän kokeen maailman, kartan ja julkiset tapahtumat. Sulje palvelin painamalla Ctrl+C. Maailma ei etene vain siksi, että katselin on auki.

4. Kokeile laboratorioajoa ilman mallia#

Seuraavassa skenaariossa on valmiit testitoiminnot (stub_actions). Se testaa kokeen ajamista ja tulosten tallentamista, ei kahden oikean mallin laatua.

LAB_OUTPUT_DIR="$(mktemp -d)"
python3 -m scripts.character_lab \
  --scenario content/characterlab/simple_prompt_comparison.json \
  --output "$LAB_OUTPUT_DIR/comparison.json"

CharacterLab luo kokeille erilliset lähtömaailman kopiot ja käyttää samaa WorldStore-validointia kuin tavallinen ajo. Tulokset jäävät annettuun JSON-tiedostoon. Kokeen väliaikaiset maailmat poistetaan ajon lopuksi.

Entä oikea mallivertailu?#

Valitse ensin, mitä haluat pitää vakiona:

Koe Pidä samana Vaihda
Päätöksentekijän vertailu Lähtötila, sisältö, teot, vuorobudjetti ja mittarit Asukasmalli tai sen ohjeistus
Kehittäjän vertailu Lähtöcommit, tehtävä, sallitut työkalut ja hyväksymiskriteerit Koodaava malli
Uusi toteutus Maailman tavoite ja keskeiset sopimukset Toteutus ja tarvittaessa teknologiat

CharacterLab-skenaarion strategiassa cognition voi valita tuetun mallireitin ilman hahmon pysyvän profiilin muuttamista. Oikeassa mallikokeessa stub_actions jätetään pois ja haluttu palvelu määritetään erikseen. Paikallinen reitti käyttää nykyistä keskitettyä paikallismallin asetusta. Hermes-reitti tarvitsee toimivan Hermes-asennuksen ja palveluntarjoajan käyttöoikeudet.

Pelkkä ajajan --model-argumentti ei takaa kaikkien hahmojen mallin vaihtumista. Hahmokohtainen cognition ja adapterin reititys vaikuttavat valintaan. Esimerkiksi oletus-Hermes-adapteri käyttää omaa oletusmalliaan, ellei hahmokohtainen asetus valitse muuta. Tarkista todellinen reitti ja asetukset kokeen todisteista.

Vertaa hyväksyttyjä ja hylättyjä tekoja, tavoitteiden toteutunutta etenemistä, toistoa, vuorojen kattavuutta, virheitä, latenssia ja saatavilla olevaa käyttötietoa. Sama siemen ei takaa etäpalvelun täysin toistettavaa vastausta, eikä yksi onnistunut tarina todista yleistä parannusta.

Nykyisen maailman samasta hetkestä alkava vertailu tarvitsee erikseen otetun tilannekopion. GameLab on olemassa tätä varten: se lukee lähdemaailman hallitusti ja ajaa kokeet kopioissa. Pelkkä Git-klooni tai julkinen Pages-sivu ei sisällä tuota lähtötilannetta.

Tarkemmat asetukset ja rajat: CharacterLab ja GameLab, malliadapteri ja maailman ajaminen.

Jos tarkoitus on antaa uuden mallin rakentaa peli itse, jatka oman version lähtökuvaukseen.
